WORK_RULES:
- Одна задача = один технический шаг.
- Изменения выполнять маленькими точечными итерациями.
- Перед следующим шагом фиксировать факт завершения предыдущего.
- Не смешивать в одном шаге: диагностику, рефакторинг, бизнес-правки, визуальные правки, docker/dev/prod, документацию.
- Если задача расширяется, остановиться и предложить следующий короткий шаг.

BUG_DIAGNOSTICS_RULES:
- При баг-репорте не чинить "похожий" участок по догадке.
- Сначала диагностировать цепочку: UI -> JS -> API -> backend -> DB/response.
- Обязательно получить status/response проблемного API.
- При 500: смотреть traceback/logs.
- При "UI пустой/не реагирует": проверить console и Network.
- При 404: проверить registered routes.
- После рефакторинга: проверить импорты, декораторы, conflicts роутов и response schema.
- Сначала назвать точную причину, только потом делать фикс.
- Не маскировать ошибки fallback-заглушками и пустым UI.
- Не коммитить до минимальной проверки исправления.
- После фикса всегда показать:
  - точную причину;
  - изменённые файлы;
  - проверку, подтвердившую исправление;
  - (для UI-багов) endpoint/status/response до и после.

MODULARITY_RULES:
- Не добавлять новые крупные фичи в монолитные файлы, если можно вынести в модуль.
- Backend:
  - router должен быть тонким;
  - бизнес-логику выносить в services;
  - не раздувать `settings.py`, `telegram.py`, `tickets.py`, `schema_evolution.py`;
  - фичи кнопок бота выносить в отдельные bot-buttons router/service;
  - фичи Telegram runtime выносить в `telegram_*` services;
  - фичи заявок выносить в `ticket_*` services.
- Frontend:
  - не раздувать `ticket.js`, `settings_bot_buttons.js`, `list.js`;
  - крупные блоки выносить в отдельные JS-модули;
  - не дублировать sidebar-логику;
  - не добавлять большие несгруппированные секции в `styles.css`.

REFACTOR_RULES:
- Если задача на вынос кода, исходный файл должен реально уменьшиться.
- Не копировать код с дублями.
- После выноса обязательно показать:
  - строки до/после в исходном файле;
  - какие функции удалены из исходного файла;
  - где функции находятся теперь;
  - подтверждение отсутствия дублей;
  - `git diff --stat`.

  - `storage/attachments/**`
