# Синтаксис TG buttons

Этот файл описывает формат `.txt`-файлов меню Telegram-бота. Если в будущем появятся новые возможности, этот файл нужно дополнять.

## Верхнее меню

В начале файла указывается раскладка кнопок. Кнопки в одной строке Telegram будут стоять рядом.

```text
Для "Руководство":
[Кнопка 1] [Кнопка 2]
[Кнопка 3]
[Кнопка 4] [Кнопка 5]

Далее будут указаны тип и тексты, которые должны отправляться при нажатии на указанные кнопки:
```

## Обычная заявка

```text
[Название кнопки] - тип Заявка, текст:
"Текст, который бот отправит клиенту после выбора кнопки."

Инструкция:
"Внутренняя инструкция для сотрудника. Клиент её не видит."
```

## Задача

```text
[Название кнопки] - тип Задача, текст:
"Следующим сообщением отправьте описание задачи.

Не разбивайте информацию на несколько сообщений."

Инструкция:
"Инструкция для сотрудника."
```

## Автоматическая заявка

```text
[Название кнопки] - тип Автоматическая заявка, текст:
"Текст для клиента."
```

## Подменю

```text
[Учебные материалы] - тип Подменю, текст:
"Выберите необходимый материал по кнопке ниже"
    Кнопки подменю:
    [Памятка 1] - тип Автоматическая заявка, текст: "Файл в разработке"
    [Памятка 2] - тип Автоматическая заявка, текст: "Файл в разработке"
```

## Групповая задача

```text
[Уволить сотрудника] - тип групповая задача, текст:
"Опишите задачу одним сообщением."

    Подзадачи:
    [Подзадача 1] - тип Задача, инструкция:
    "Инструкция для первой подзадачи."

    [Подзадача 2] - тип Задача, инструкция:
    "Инструкция для второй подзадачи."

Конец подзадач для кнопки [Уволить сотрудника]
```

## Автоматизация

Строка `Автоматизация:` добавляет специальную обработку к кнопке. Кнопка при этом сохраняет свой основной тип.

Текущие automation key:

`bitrix_deal_phone_lookup` — применяется к кнопке типа `Задача`.

Логика:
- клиент отправляет номер сделки (5–7 цифр) или ссылку вида `/crm/deal/show/<id>/`;
- при успехе клиенту отправляется только найденный номер телефона;
- если автоматизация не сработала, задача передаётся сотруднику.

## Ответственный

Строка `Ответственный:` позволяет принудительно назначить обращение на конкретного сотрудника.

```text
Ответственный: login:ivanov
Ответственный: user_id:00000000-0000-0000-0000-000000000001
```

Правила:
- строка необязательная;
- если сотрудник найден, `is_active=true`, роль `agent` или `trainee` — заявка/задача назначается на него независимо от `availability_status`;
- если сотрудник не найден/неактивен/роль не подходит — обращение уходит в обычное распределение;
- клиент не видит техническую ошибку;
- в заявке создаётся `system`-сообщение о fallback.

## Подтверждение (Да/Нет)

Строка `Подтверждение:` добавляет промежуточный шаг перед созданием обращения.

- `Да` — продолжает сценарий кнопки.
- `Нет` — отменяет выбор и возвращает в меню.
- До подтверждения обращение не создаётся.

## Инструкция

Рекомендуемая директива:

```text
Инструкция:
"..."
```

Инструкция сохраняется в карточке заявки и открывается сотруднику по кнопке `Инструкция` (в чат как `system`-сообщение больше не добавляется).

Для обратной совместимости также поддерживаются старые варианты:

Допустимы оба варианта написания:

```text
Текст системный:
"..."
```

```text
текст системный:
"..."
```

Приоритет: если в кнопке указаны и `Инструкция:`, и `Текст системный:`, используется `Инструкция:`.

## Шаблонные поля

В текстах можно использовать шаблонные поля в двойных фигурных скобках.

Подробный список полей:

```text
TG buttons/Использование полей.md
```

## Файлы в автоматических кнопках

Поддерживаются два варианта:

1. Прямой файл:

```text
файл: "Название файла.pdf"
```

2. Условный файл:

```text
если {{location_type}} = Офисный, файл: "Название файла.pdf"
```

Совместимость:
- `фаил:` поддерживается для обратной совместимости;
- в новых конфигах рекомендуется `файл:`;
- оба варианта рабочие: `файл: "..."` и `фаил: "..."`.

Где должны лежать файлы:
- на хосте: `TG buttons/files`;
- в контейнере: `/button-config/files`.

Поиск:
- если указано `файл: "Памятка.pdf"`, система ищет `TG buttons/files/Памятка.pdf` (в контейнере `/button-config/files/Памятка.pdf`);
- если указан подпуть, например `файл: "materials/file.pdf"`, он трактуется как относительный внутри `TG buttons/files`.

Ограничения безопасности:
- абсолютные пути запрещены;
- `../` (path traversal) запрещён.

## Важные правила

- Название кнопки в верхнем меню должно совпадать с названием блока ниже.
- Текст кнопки лучше заключать в двойные кавычки.
- Если внутри текста нужна кавычка, используйте одинарные кавычки.
- Переносы строк внутри кавычек сохраняются.
- Если у кнопки нет `Инструкция:` (или старого `Текст системный:`), значит инструкция не нужна.
- Если у кнопки нет `Автоматизация:`, она работает по обычной логике своего типа.
- Черновики храните в папке `TG buttons/черновики`, они не должны применяться как боевое меню.
