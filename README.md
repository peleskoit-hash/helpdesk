# Helpdesk (local MVP)

Локальный helpdesk с Telegram-ботом и web-интерфейсом для обработки заявок/задач.

## Запуск

```bash
docker compose up --build
```

- API: `http://localhost:8000`
- Swagger: `http://localhost:8000/docs`

## Аутентификация

- Реализована серверная авторизация по `login/password`.
- Используются `GET /login`, `POST /login`, `POST /logout`.
- Защищённые HTML-страницы без сессии редиректят на `/login`.
- Защищённые API без сессии возвращают `401/403`.
- Сессия cookie-based (`httpOnly`), роль/права проверяются на backend.

## Страницы

- `/tickets` — список заявок
- `/tickets/{id}` — карточка заявки
- `/settings` — главная настроек (admin)
- `/settings/users` — настройка пользователей (admin)
- `/settings/client-card` — настройка карточки клиента (admin)
- `/settings/bot-buttons` — конструктор/настройки кнопок бота (admin)
- `/statuses` — быстрое управление статусами сотрудников (admin)

## Роли

- `admin` — полный доступ
- `agent` (`Сотрудник`) — рабочий доступ
- `trainee` (`Стажёр`) — как сотрудник, но без автоназначения
- `chiki_piki` — read-only наблюдатель по "Колл Центру"

## Telegram меню и DB-only

- Проект поддерживает DB-only меню кнопок с runtime-флагом `USE_DB_BUTTONS`.
- При `USE_DB_BUTTONS=true` меню/действия берутся из БД.
- Текстовые файлы `TG buttons/*.txt` сохраняются как резерв/эталон.

### Профили меню (menu profiles)

- Поле клиента `ClientProfile.destination` ("Куда?") определяет, какой профиль меню показывать клиенту в Telegram.
- Один профиль меню может быть привязан к нескольким значениям "Куда?".
- Одно значение "Куда?" может быть привязано только к одному профилю.
- `Базовое` используется как fallback, если явной привязки нет.

## Настройки кнопок (Настройки → Кнопки бота)

Для конечных кнопок доступны настройки:
- название (label override);
- активность (`is_enabled`);
- инструкция;
- текст системный;
- текст клиенту;
- подтверждение;
- фиксированный ответственный;
- `freeze_on_create`;
- файлы;
- условные файлы;
- `automation_key`;
- раскладка строк (`layout rows`, до 2 кнопок в ряд).

## Completion stats

- В sidebar для `agent/trainee` отображается статистика выполненных заявок/задач:
  - всего;
  - год/месяц/неделя/день;
  - Legacy отдельно.
- Для `admin/chiki_piki` показывается только плашка пользователя (без расширенной статистики).

## Onsite trigger

- Для обычных `ticket` реализован триггер фразы "Иду к вам" (без учёта регистра).
- При срабатывании:
  - статус агента меняется на "На заявке";
  - в этой заявке кнопка закрытия меняется на "Решил на месте";
  - после закрытия добавляется служебное напоминание агенту про возврат статуса в "В сети".

## Важно

- Все файлы проекта в UTF-8.
- Секреты и токены в документацию не добавлять.
- Для Windows/dev проект читает локальный `.env`.
- Для локального dev используйте отдельный dev bot token и перенесите его в локальный `.env` на основе `.env.dev.example`.
- Для Ubuntu/prod используйте только `.env.prod` с отдельным prod bot token.
- Запрещено одновременно запускать polling в dev и prod на одном и том же `TELEGRAM_BOT_TOKEN`.
